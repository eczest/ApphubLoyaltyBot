# AppHub

Telegram-бот программы лояльности физического магазина AppHub. Русский интерфейс, регистрация по собственному Telegram-контакту, бонусная карта с QR, продажи аксессуаров, подтверждённые покупателем списания, рефералы, сотрудники и администратор. CRM, касса и рекламные рассылки не подключены. Номер чека — идентификатор ручной операции, а не подтверждение реальной оплаты.

## Стек и структура

Go (модуль совместим с 1.26.5+, Docker собирает на 1.27.3), `github.com/go-telegram/bot`, pgx/v5, PostgreSQL 17, slog, Docker Compose. Один процесс, long polling, один последовательный обработчик Telegram и фоновая обработка истечения резервов/уведомлений. Финансовая корректность обеспечивается PostgreSQL, а не порядком Telegram-обновлений.

```text
cmd/bot/                запуск, миграции, singleton polling lock, SIGTERM
internal/config/        переменные окружения
internal/security/      контакт, телефон, токены, целочисленная арифметика
internal/storage/       регистрация, роли, транзакции, диалоги, аудит
internal/telegram/      русские меню, пошаговые сценарии, outbox
migrations/             SQL + встроенная миграция
deploy/                 согласие, резервное копирование, отчёт проверок
```

Слой хранения выполняет бизнес-операции целиком внутри транзакций. Отдельные пакеты-фасады без поведения не добавлены. Будущая CRM может вызывать эти же операции со стабильным ID покупки и уникальным чеком.

## Подготовка бота и конфигурации

1. Откройте проверенного `@BotFather` в Telegram, выполните `/newbot`, задайте имя и username, сохраните токен.
2. В BotFather через `/setcommands` можно задать `start — Главное меню`, `register — Регистрация`, `cancel — Отмена действия`. Не включайте webhook.
3. Узнайте свой числовой Telegram ID через доверенный источник. `ADMIN_TELEGRAM_ID` — именно ID пользователя, не username и не ID группы.
4. Скопируйте `.env.example` в `.env`, задайте токен, ID и сильный уникальный пароль PostgreSQL. Не публикуйте `.env`.

```sh
cp .env.example .env
chmod 600 .env
openssl rand -hex 24
```

Впишите пароль в `POSTGRES_PASSWORD` и в `DATABASE_URL` вместо `CHANGE_ME`. Пароль в URL должен быть percent-encoded, если содержит специальные символы; hex-пароль упрощает настройку. Для Compose хост базы — `postgres`, для локального запуска — `127.0.0.1`. `sslmode=disable` допустим здесь для внутренней Docker-сети/localhost; удалённая база требует TLS.

| Переменная | Назначение |
|---|---|
| BOT_TOKEN | Секрет BotFather |
| ADMIN_TELEGRAM_ID | Первоначальный администратор, положительный int64 |
| POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB | Первичная инициализация PostgreSQL |
| DATABASE_URL | Полная строка подключения приложения |
| TZ | Часовой пояс, по умолчанию Europe/Moscow в Compose |
| STORE_ID / REGISTER_ID | Область уникальности чека, по умолчанию main/main |
| STORE_CONTACTS | Адрес, телефон и часы магазина, обычный текст |


Телефоны хранятся в PostgreSQL в открытом виде, чтобы обеспечить поиск и уникальность. Ограничьте доступ к VPS, используйте шифрование диска и зашифрованные внешние резервные копии, SSH-ключи и обновления ОС. В Telegram отображается только маска, в QR — только случайный токен карты. В логах приложения нет текстов сообщений, телефонов и токена. Сервисные сообщения отправляются только в личном чате.

## Ubuntu 22.04 / 24.04 VPS

Подойдёт 1 vCPU / 2 GB RAM / 20 GB SSD. Установите Docker Engine и Compose plugin из официального apt-репозитория:

```sh
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
printf 'deb [arch=%s signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu %s stable\n' "$(dpkg --print-architecture)" "$VERSION_CODENAME" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version
```

Далее команды Docker выполняйте с `sudo`, если у текущего пользователя нет доступа к daemon. Членство в группе docker даёт права уровня root. Клонируйте свой Git-репозиторий проекта, настройте `.env`, затем из каталога проекта:

```sh
docker compose up -d --build
docker compose logs -f apphub-bot
docker compose restart apphub-bot
docker compose down
```

Порт PostgreSQL наружу не опубликован. Сохраняйте доступ по SSH; бот не требует входящих HTTP-портов, домена и HTTPS. Нужен исходящий доступ к Telegram и при сборке — Docker registry/Go module proxy.

Миграция автоматически применяется на старте в транзакции под advisory lock до начала polling. Можно запустить отдельно:

```sh
docker compose up -d postgres
docker compose run --rm apphub-bot migrate
```

Миграции уже применённой версии не повторяются. Не редактируйте `001_init.sql` после ввода базы в эксплуатацию. Для изменения схемы добавляйте следующую SQL-миграцию и её выполнение/учёт версии в `Migrate`; проект содержит версии 001–003. Откатывать схему нужно из проверенного backup, финансовые записи физически не удалять.

Начальный администратор создаётся/активируется при каждом старте из `ADMIN_TELEGRAM_ID`. Остальные пользователи автоматически прав не получают. Менять первоначального администратора следует владельцу через `.env` и контролируемый доступ к базе: старый ADMIN не удаляется автоматически. Меню позволяет выдавать только роль EMPLOYEE.

## Локальный запуск

Установите Go 1.26.5+ и PostgreSQL. Создайте отдельную базу и пользователя, заполните `.env`, указав localhost в `DATABASE_URL`. Приложение читает окружение; Compose читает `.env` автоматически. В доверенной локальной shell конфигурацию можно экспортировать:

```sh
set -a
. ./.env
set +a
go mod download
go run ./cmd/bot migrate
go run ./cmd/bot
```

Файл для shell должен содержать корректные shell-присваивания: значения с пробелами заключайте в кавычки. Вариант через Docker избавляет от локальной установки Go и PostgreSQL.

## Простой сценарий программы

Покупатель открывает `/start`, нажимает «📱 Поделиться номером». Принимается только собственный контакт Telegram с совпадающим user_id. Имя, пароль и почта не требуются. Повторная регистрация не создаёт новый аккаунт. Телефон, занятый другим Telegram ID, автоматически не перепривязывается.

В меню покупателя: «Мои бонусы», «Приведи друга», «История операций», «Контакты». В балансе только доступное количество бонусов и информация об оплате до 50% стоимости аксессуаров. Правила и настройки убраны. «Моя карта» удалена из меню. Номер карты вводить для начислений не требуется.

`STORE_CONTACTS` предназначен для ссылки на общий Telegram-канал магазина. Актуальная ссылка: https://t.me/apphub_store.

### Начисление продавцом

1. «Найти клиента» → телефон (либо значение отсканированного QR).
2. «Начислить бонусы» → количество бонусов.
3. Бонусы сразу зачислены, покупатель получает уведомление.

Также можно начать с «Начислить бонусы»: бот сначала спросит телефон. Сумма покупки, номер чека и процент кешбэка для начисления не нужны. Продавец сам выбирает положительное целое количество бонусов. Автоматического кешбэка для новых покупок нет. Повтор обработки одного начисления не меняет баланс дважды. В истории и аудите остаются сумма и сотрудник; исправление ошибки — через администратора с причиной.

### Приведи друга

Покупатель делится ссылкой `https://t.me/USERNAME?start=ref_TOKEN`. Друг открывает её и впервые регистрируется своим контактом. В одной транзакции начисляется по **500 бонусов обоим**, без ожидания покупки. Бонусами оплачиваются только аксессуары, до 50% их стоимости. Повторная регистрация, чужой контакт, занятый телефон и ссылка существующего клиента не дают повторной награды. Самоприглашение исключено.

Награда за регистрацию не связана с последующей покупкой и не отменяется при её возврате. Старые операции сохраняются как были. Миграция не выдаёт награды задним числом уже зарегистрированным клиентам и старым ожидающим приглашениям. Старые награды, привязанные к покупкам, компенсируются по их прежней процедуре при возврате.

### Списание

«Списать бонусы» → клиент → стоимость только аксессуаров → желаемые бонусы. Стоимость нужна для серверной проверки `min(доступный баланс, стоимость * 50 / 100)`. Покупатель подтверждает запрос в своём чате. После реальной оплаты продавец нажимает «✅ Завершить списание» и подтверждает оплату. Вводить технический ID и чек не нужно: внутренний уникальный идентификатор создаётся автоматически.

Запрос подтверждения действует 5 минут, подтверждённый резерв — 15 минут. Отмена/истечение освобождают бонусы. Резерв хранится в БД для защиты от одновременных списаний, но не показывается отдельной строкой в «Моих бонусах». После списания автоматического начисления нет: продавец при необходимости отдельно начисляет выбранное количество бонусов.

### Администратор

- «Сотрудники»: `123456789 1` добавляет/включает EMPLOYEE, `123456789 0` блокирует. ADMIN из Telegram не выдаётся.
- «Корректировка» убрана из Telegram, включая старые кнопки. Ранее проведённые корректировки сохранены в истории.
- «Статистика» и «Журнал» сохранены.
- «Возврат покупки» доступен администратору для полного возврата ранее списанных бонусов, по ID из истории и с причиной. Ручное начисление не связано с покупкой: его исправляют отдельной корректировкой.

Настройки процентов и размера награды, а также восстановление убраны из Telegram-интерфейса. Старые кнопки этих действий не выполняются. В базе сохранены исторические поля и операции, чтобы обновление не удаляло данные.

## Надёжность и эксплуатационные ограничения

Операции и диалоги сохранены в PostgreSQL. Диалог ввода устаревает через 24 часа, сроки финансовых запросов независимы. Баланс и резерв защищены CHECK, транзакциями и блокировками строк. Реферальные и финансовые записи защищены уникальными индексами. Изменения сотрудников, ручные начисления и корректировки сохраняются в аудите. Лимит чувствительных действий — 40 обновлений в минуту на Telegram ID, хранится в БД.

Один активный polling-процесс на общую базу обеспечивается выделенным соединением с PostgreSQL advisory lock. При потере этого соединения приложение останавливает polling; Compose перезапускает контейнер и pgx создаёт новые соединения. **Не запускайте тот же Telegram-токен с другой независимой базой или сторонним polling/webhook-клиентом**: межбазовой блокировки нет, Telegram вернёт conflict. После первого развёртывания удалите ранее настроенный webhook через Bot API, если он существовал.

Обычные сервисные финансовые уведомления доставляются через outbox с повторами (до 20 попыток через 5 минут). При сбое между отправкой и отметкой доставки уведомление может повториться; финансовая операция не повторяется. После 20 неуспехов запись сохраняется для ручной проверки. Запрос подтверждения отправляется сразу: при явной ошибке отправки покупка отменяется, при аварийном завершении истекает сама. Если покупатель заблокировал бота, продавец должен попросить его разблокировать бота; баланс и история остаются в базе.

## Резервное копирование и восстановление

Named volume `postgres_data` сохраняет базу при `restart`, `down` и пересоздании контейнеров. **Не используйте `docker compose down -v` на рабочем проекте** — это удаляет volume. Данные Docker Desktop или самого VPS тоже могут быть потеряны: volume не заменяет внешний backup. Имя Compose-проекта/каталог должно оставаться постоянным, иначе Compose создаст другой volume.

```sh
./deploy/backup.sh /secure/path/apphub.dump
# либо вручную:
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > apphub.dump
```

Храните ежедневные копии вне VPS, ограничьте права, шифруйте и периодически проверяйте восстановление. Для восстановления остановите бот; следующий пример **заменяет содержимое выбранной базы** из копии:

```sh
docker compose stop apphub-bot
# Для существующей базы: --clean удаляет объекты перед восстановлением.
docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner --exit-on-error' < apphub.dump
docker compose up -d apphub-bot
```

Для безопасной проверки восстановите сначала в отдельную БД/проект, проверьте количество клиентов и суммы ledger. Токен рабочего бота в проверочной среде не включайте.

Проверка сохранности на вашем VPS: зарегистрируйте тестового клиента, запишите карту и баланс; выполните `docker compose restart`, затем `docker compose down` и `docker compose up -d`; убедитесь, что карта/баланс/история не изменились. Повторите после `sudo systemctl restart docker`. Операции Telegram требуют реального тестового бота и контакта.

## Обновление и логи

```sh
./deploy/backup.sh apphub-before-update.dump
git pull --ff-only
docker compose up -d --build
docker compose logs --tail=100 apphub-bot
docker compose ps
```

Не храните backups в публичном Git. В Compose ротация логов ограничена 3 × 10 MB на сервис. Следите за свободным местом, актуальностью backup и очередью `SELECT count(*) FROM outbox WHERE sent_at IS NULL AND attempts>=20;`.

## Тесты

```sh
go test ./...
go vet ./...
go build ./cmd/bot
# Интеграционные тесты создают/удаляют собственные схемы в указанной базе.
# Нужны права CREATE SCHEMA; используйте отдельную тестовую базу.
TEST_DATABASE_URL='postgres://USER:PASS@127.0.0.1:5432/apphub_test?sslmode=disable' go test -race -count=1 ./...
```

Без TEST_DATABASE_URL интеграционные тесты явно пропускаются. Они проверяют регистрацию и повторы, чужой контакт и дубли телефонов, роли/блокировку, ручное начисление без покупки, уникальность операции, повторное подтверждение, лимит и недостаток баланса, параллельные резервы, отмену/истечение, возврат, по 500 бонусов за регистрацию друга, отсутствие повторов и независимость новых наград от возврата, совместимость прежнего восстановления и чтение сохранённых данных через новое соединение. Unit-тесты проверяют нормализацию, принадлежность контакта, округление и токены. Для полного приёмочного прогона нужны реальные Telegram-клиенты покупателя/сотрудника; автоматические тесты не подтверждают доставку через живой Telegram.

## Типичные ошибки

- `database unavailable`: проверьте healthcheck PostgreSQL, одинаковые пароли в URL и POSTGRES_PASSWORD, имя хоста `postgres`. Изменение POSTGRES_PASSWORD в `.env` не меняет пароль уже созданной БД — измените его в PostgreSQL согласованно, не удаляйте volume.
- `another polling instance holds database lock`: остановите второй процесс с этой базой. Не масштабируйте сервис бота.
- Telegram initialization failed/conflict: проверьте токен, доступ к api.telegram.org, отсутствие webhook и второго клиента. Не включайте debug-логи с токеном.
- Номер уже зарегистрирован: обратитесь к владельцу магазина для проверки привязки. Самостоятельного переноса и автоматического объединения нет; восстановления в Telegram-меню больше нет.
- Действие устарело: запрос/резерв истёк или отменён; начните новую покупку. Старые кнопки не создают повторные движения.
- Чек уже использован: проверьте реальный номер, магазин/кассу и историю. Возврат не освобождает уникальность чека; новый документ должен иметь новый идентификатор.
- Нет уведомления: покупатель должен открыть и не блокировать бота; проверьте outbox и сеть. Состояние операции проверяйте по базе/истории.
- Docker daemon недоступен: запустите Docker Engine (`sudo systemctl start docker`) или Docker Desktop.

Фактический отчёт текущей проверки: [deploy/VERIFICATION.md](deploy/VERIFICATION.md). Инструкция установки сверена с [официальной документацией Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/); версии Go — с [go.dev/dl](https://go.dev/dl/).
